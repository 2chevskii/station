# Роли и задачи

Роль объединяет упорядоченные задачи, необязательные значения по умолчанию и файлы. Роли выбираются в корневом списке `roles`. Локальная роль находится в `roles/<имя>/`; плагин может экспортировать роли в собственном пространстве имён.

## Формы YAML-роли

`role.yaml` может быть списком задач:

```yaml
- name: Установить Git
  winget:
    id: Git.Git
    state: present
```

Также допустим объект с обязательным `tasks` и необязательными `description` и `defaults`:

```yaml
description: Настраивает Git.
defaults:
  git_config_path: "{{ user_home }}/.gitconfig"
tasks:
  - name: Создать конфигурацию Git
    template:
      template: git/config
      destination: "{{ git_config_path }}"
```

Отдельный `defaults.yaml` или `defaults.js` необязателен. Встроенные значения `defaults` переопределяют значения из этого файла, а корневые переменные переопределяют оба источника. `role.js` — отдельный формат; см. [Роли на JavaScript](./javascript-roles.md).

## Контракт задачи

Задача — объект с необязательным `name` и **ровно одним ключом модуля**. Параметры находятся внутри этого ключа и должны быть объектом. Ключ `target` в задаче не используется.

```yaml
- name: Установить ripgrep
  scoop:
    name: ripgrep
    state: present
```

Без `name` корневые задачи получают имена `station.tasks.1`, `station.tasks.2` и далее. Задачи роли получают имена `<имя-роли>.tasks.1`, `<имя-роли>.tasks.2` и далее. Сначала выполняются корневые задачи, затем задачи выбранных ролей в указанном порядке.

Ссылки на модули и роли могут содержать полные имена, например `station.builtin.copy` и `station.local.git`. Короткое имя, например `copy` или `git`, разрешается только при однозначности внутри соответствующего пространства имён. Если несколько плагинов экспортируют одно короткое имя, укажите полное.

## Проверка и выполнение

Station обрабатывает задачи по порядку. В режиме `validate` он связывает параметры и проверяет каждую задачу без выполнения. В режимах `check` и `apply` он связывает параметры, проверяет и выполняет текущую задачу, затем переходит к следующей. `check` использует `ExecutionMode.Check`, `apply` — `ExecutionMode.Apply`. Модули сообщают о необходимых правах администратора при проверке. Ошибка применения останавливает последующие задачи.
