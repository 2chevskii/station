# Роли и переменные на Lua

Station выполняет `role.lua`, `defaults.lua` и `vars/*.lua` через [NLua](https://github.com/NLua/NLua). Корневой манифест остаётся `station.yaml`. Для каждой роли выбирайте один файл задач и один файл значений по умолчанию: несколько форматов одного артефакта неоднозначны. Lua defaults можно сочетать с ролью на YAML или JavaScript.

## Переменные

Файл переменных возвращает ровно одну таблицу со строковыми ключами:

```lua
-- roles/editor/defaults.lua
return {
    editor_directory = ref('user_home') .. '/.config/editor',
    enabled = true,
    retries = 3,
    extensions = { 'lua', 'yaml' },
    options = {},
    excluded = array()
}
```

`vars/*.lua` использует тот же контракт. Файлы переменных YAML, JavaScript и Lua объединяются в порядке имён. Глобальная таблица `vars` содержит ссылки на переменные, видимые на этом этапе. Например, следующий файл может вернуть `{ selected_theme = vars.theme }`. Defaults роли выполняются до корневых переопределений, с пустой таблицей `vars`; используйте в них `ref('path')` для ссылок.

Таблицы со строковыми ключами становятся объектами. Последовательные целочисленные ключи от 1 становятся упорядоченными массивами. `{}` — пустой объект, `array()` — пустой массив; поддерживается и `array('first', 'second')`. Смешанные, разреженные, циклические и слишком глубоко вложенные таблицы отклоняются. Lua `nil` удаляет элемент таблицы, поэтому явный null-элемент таким способом не задаётся. Числа, логические значения и строки UTF-8 сохраняют типы; функции и userdata недопустимы как значения конфигурации.

## Задачи

`role.lua` регистрирует задачи через `task(module, parameters)` или `task(name, module, parameters)`. Параметры должны быть объектом. Файл роли не возвращает значения.

```lua
-- roles/editor/role.lua
task('Render editor settings', modules.template, {
    template = 'editor/settings.json',
    destination = vars.editor_directory .. '/settings.json'
})

task(modules.copy, {
    file = 'editor/keybindings.json',
    destination = vars.editor_directory .. '/keybindings.json'
})
```

`modules` содержит имена встроенных модулей `copy`, `template`, `script`, `winget`, `scoop` и `apt`. Для собственного модуля передайте строкой короткое или полное имя. Порядок регистрации определяет порядок выполнения; задачи можно создавать обычными циклами и функциями Lua.

`vars.editor_directory`, вложенные ссылки вроде `vars.editor.theme` и `ref('editor.theme')` сохраняют ссылки на переменные в объектной модели Station. Конкатенация через `..` и `tostring` создаёт выражение Scriban, которое разрешается в итоговой области переменных задачи после переопределений. Эти ссылки — плейсхолдеры; для арифметики и условий при генерации конфигурации используйте литералы Lua.

## Выполнение

Lua-роли задают задачи; defaults помещайте в `defaults.lua`. Описание и встроенные defaults доступны в формате YAML-роли. Каждый файл выполняется в новом состоянии Lua. `require('helper')` загружает `helper.lua` рядом с текущим артефактом. Файлы-помощники непосредственно в `vars/` также обнаруживаются как файлы переменных, поэтому помещайте такие помощники в подкаталог.

`print(...)` пишет диагностику в stderr. Выполнение ограничено бюджетом 100 000 инструкций и проверкой двух секунд процессорного времени на интервалах hook. Эти проверки относятся к инструкциям Lua; блокирующие нативные вызовы выходят за пределы ограничения. Скрипты имеют стандартные библиотеки и права интеграции NLua, поэтому используйте доверенные конфигурации.

Полный пример находится в [роли luaexample](https://github.com/2chevskii/station/tree/main/examples/workstation/roles/luaexample). Для её запуска выберите `luaexample` в `station.yaml`.
