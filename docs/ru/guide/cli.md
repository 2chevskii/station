# Командная строка

Ниже `station` — условное обозначение CLI. Опубликованный файл Windows называется `Station.Cli.exe`; при разработке из корня репозитория используйте `dotnet src/Station.Cli/bin/Debug/net10.0/Station.Cli.dll`.

```text
station restore       --config <каталог> [параметры]
station explain       --config <каталог> [параметры]
station list roles    --config <каталог> [параметры]
station list modules  --config <каталог> [параметры]
station validate      --config <каталог> [параметры]
station check         --config <каталог> [параметры]
station apply         --config <каталог> [параметры]
```

| Команда | Действие |
| --- | --- |
| `restore` | Разрешает заявленные плагины и показывает их источники и расположение. |
| `explain` | Показывает статическое дерево задач, связанные параметры и видимые переменные. |
| `list roles` | Показывает доступные роли, описания и источники. |
| `list modules` | Показывает доступные модули, описания и источники. |
| `validate` | Восстанавливает плагины, разрешает задачи, связывает параметры и вызывает проверку модулей. |
| `check` | Проверяет и запускает каждую задачу в режиме оценки изменений. |
| `apply` | Проверяет и выполняет каждую задачу по порядку. |

Все команды принимают параметры:

| Параметр | Значение |
| --- | --- |
| `--config <каталог>` | Корень конфигурации; по умолчанию текущий каталог. |
| `--set key=value` | Переопределить переменную. Можно повторять. Для вложенных ключей используйте точки, например `--set git.user=Alex`. Значения передаются как строки. |
| `--plugin-cache-dir <путь>` | Переопределить корень кеша плагинов. Относительные пути отсчитываются от корня конфигурации. |

Справку по команде выводит `station <команда> --help`. Код завершения при успехе — `0`, при ошибке — `1`.

## Рекомендуемый порядок

```powershell
station list modules --config ./workstation
station explain --config ./workstation
station validate --config ./workstation
station check --config ./workstation
station apply --config ./workstation
```

`explain` и команды инвентаризации могут восстанавливать плагины для обнаружения их экспортов. `validate`, `check` и `apply` тоже делают это автоматически. `check` вызывает каждый модуль в режиме проверки; собственный модуль должен сам учитывать этот режим. `apply` останавливается при ошибке задачи и показывает записи уже выполненных задач.
