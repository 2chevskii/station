# Решение проблем

Начните с `station explain --config <каталог>`, чтобы увидеть имена, параметры и видимые переменные. Команды `station list roles` и `station list modules` показывают обнаруженные компоненты. `station validate` сообщает об ошибках параметров, файлов и прав без выполнения задач.

## Конфигурация не загружается

Проверьте, что `--config` указывает на существующий каталог с `station.yaml`, а поле `roles` содержит непустой список. Каждой выбранной роли нужен `role.yaml`, `role.js` или `role.lua` в каталоге роли. В задаче должен быть ровно один ключ модуля со вложенным объектом параметров.

Если Station сообщает о неоднозначных файлах переменных или ролей, удалите дублирующий формат: храните один файл `role.*` и один файл `defaults.*` на роль, а также один файл с каждым базовым именем в `vars/` среди форматов YAML, JavaScript и Lua.

## Неоднозначное имя роли или модуля

Выведите доступные имена и используйте указанное полное имя. Локальные роли и модули начинаются с `station.local`, встроенные модули — с `station.builtin`, экспорты плагина — с поля `name` его манифеста.

```powershell
station list roles --config ./workstation
station list modules --config ./workstation
```

Пространства имён ролей и модулей независимы. Короткое имя должно быть однозначным в своём пространстве.

## Не найден файл, шаблон или скрипт

Для `copy` проверьте `files/<логическое-имя>` в роли или корне конфигурации. Для `template` проверьте `templates/<логическое-имя>.scriban` или `.sbn`. Параметр `path` у `script` должен оставаться внутри корня задачи: корня конфигурации для корневых задач или корня роли для задач роли. Исполняемый файл `runner` должен находиться в `PATH`.

## Плагин не восстанавливается

Выполните `station restore --config <каталог>`, чтобы отдельно увидеть ошибку восстановления. Локальные требования разрешаются внутри `<корень-конфигурации>/plugins/`. Плагину нужен ровно один `manifest.yaml` или `manifest.yml` с непустыми `name` и `version`. Проверьте существование каждой экспортируемой роли и сборки модуля. Для Git, URL, NuGet и npm проверьте доступ к сети и адрес источника.

Переместить загружаемые файлы можно через `--plugin-cache-dir <путь>`; см. [Плагины](./plugins.md).

## Нужны права администратора или меняется состояние при проверке

Если при проверке сообщается о необходимости повышенных прав, запускайте `validate` из терминала администратора. Они могут понадобиться для `winget` с `scope: machine`, Scoop с `global: true` и защищённых путей назначения. Перед `apply` используйте `check` для просмотра ожидаемых изменений. Собственные модули `script` и .NET должны реализовывать режим проверки без изменения компьютера; если пробный запуск меняет состояние, проверьте их реализацию.
